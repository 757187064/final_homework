# 目录结构说明

本项目已经按“最终提交、可复现工程、过程说明、原始备份、废弃归档”重新整理。日常查看和最终上传时，优先看 `提交文件/`、`本地工程文件/`、`说明文件/`，其余目录主要用于追溯，不作为正式入口。

## 顶层目录

| 目录 | 用途 |
|---|---|
| `提交文件/` | 最终报告、图表、Prompt 记录、资源记录、实验结果证据等提交相关材料。 |
| `本地工程文件/` | 可复现代码工程、依赖文件、训练/推理脚本和运行说明。 |
| `说明文件/` | 评分标准、作业要求、任务看板、工作记录、答辩准备和组员补充说明。 |
| `原始材料备份/` | 组员传来的原始工程与外层散落文件备份；有用内容已经整理进前三个正式目录。 |
| `废弃归档/` | 旧模板、旧说明、重复报告和临时系统文件，不作为正式提交入口。 |
| `.git/`、`.gitignore` | 仓库基础文件，保留。 |

## 提交文件

`提交文件/` 只保留两个材料区和一份说明：

| 路径 | 作用 |
|---|---|
| `提交文件/01_课程提交涉及材料/` | 与课程最终提交清单直接相关的材料。 |
| `提交文件/02_补充支撑材料/` | 已有但不属于最小硬性提交清单的过程材料。 |
| `提交文件/提交文件说明.md` | 每个提交材料的作用、已有内容和待补项。 |

`01_课程提交涉及材料/` 中的重点：

- `实验报告.md`：最终 Markdown 实验报告主体。
- `图表素材/`：报告/PPT 引用图；`数据分析补充图/` 来自组员数据分析工程。
- `实验结果证据/`：四组主实验结果、Kaggle Notebook、提交文件、验证集预测图，以及扩展消融实验记录。
- `智能体Prompt记录.md`、`智能体证据/`：智能体使用记录和真实过程材料。
- `资源使用与经费记录.md`：GPU、Kaggle、Codex、token 等资源费用说明。
- `消融实验结果表.md`：主结果与消融对照口径。
- `技术博客分享稿.md`：技术博客草稿，发布后补链接。

## 本地工程文件

| 路径 | 作用 |
|---|---|
| `本地工程文件/训练与推理代码/` | 正式代码仓库主体，包含 `README.md`、`requirements.txt`、`configs/`、`scripts/`、`src/`、`tests/`。 |
| `本地工程文件/Kaggle运行指南.md` | 早期 Kaggle 运行说明，若出现乱码，以代码目录中的 `README.md` 为准。 |
| `本地工程文件/模型训练统一指南.md` | 早期模型训练说明，若出现乱码，以代码目录中的 `README.md` 为准。 |

最终提交代码仓库时，最重要的是 `本地工程文件/训练与推理代码/`。

## 说明文件

| 路径 | 作用 |
|---|---|
| `评分标准.md`、`期末汇报大作业要求.md`、`现场打分表.md` | 课程要求和评分依据。 |
| `任务看板.md`、`评分覆盖自查表.md` | 提交前检查和补漏。 |
| `01项目负责人工作记录.md` | 01 角色统筹记录。 |
| `答辩问题清单.md` | 现场问答准备。 |
| `02数据分析补充材料/` | 02 组员数据分析过程材料和 Prompt 记录。 |
| `04消融实验补充材料/` | 扩展消融计划、日志、运行说明，以及 04 号更新版消融实验汇总。 |

## 原始材料备份

`原始材料备份/组员原始工程/` 保存组员传来的原始目录：

- `02-数据分析与可视化/`
- `03_模型训练与代码实现/`
- `ablation_experiments/`
- `deep_learing_final/`

这些目录不建议作为最终提交入口。里面有用的脚本、配置、图表和结果证据已经整理到 `提交文件/`、`本地工程文件/`、`说明文件/`。

## 废弃归档

`废弃归档/` 保存旧模板、重复文件和历史版本。除非需要追溯旧材料，否则最终提交和答辩准备都不用进入这个目录。
