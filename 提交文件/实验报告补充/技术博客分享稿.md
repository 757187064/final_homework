# Kaggle 钢板缺陷检测项目复盘：从 U-Net Baseline 到消融实验

## 1. 项目背景

这次课程大作业选择的是 Kaggle 竞赛 **Severstal: Steel Defect Detection**。任务目标是识别钢板表面的 4 类缺陷，并预测缺陷所在的像素区域。它不是普通图像分类，而是语义分割任务：模型不仅要判断有没有缺陷，还要输出缺陷的大致位置。

这个赛题和深度学习课程中的 CNN、U-Net、迁移学习、数据增强、损失函数和模型评价指标都有直接关系，适合作为一次完整的课程实践。

## 2. 数据与难点

数据标注采用 Kaggle 常见的 RLE 编码格式。训练时需要把 RLE 解码成 4 通道 Mask，推理后又要把预测 Mask 编码回 `ImageId_ClassId, EncodedPixels` 的提交格式。

数据中最明显的问题是类别不平衡：

- Class 3 样本最多；
- Class 2 样本最少；
- 缺陷区域通常细长、不规则；
- 提交文件格式要求严格，每张测试图片必须对应 4 行。

因此，这个项目的难点不只在模型训练，也包括数据格式处理、提交格式检查和实验记录。

## 3. 方法设计

我们使用 U-Net + ResNet34 作为主要 Baseline。U-Net 适合分割任务，ResNet34 作为 encoder 可以提取钢板纹理和缺陷边缘特征。训练中使用 BCE Loss 与 Dice Loss 的组合，使模型同时关注像素分类和区域重叠效果。

整体流程为：

```text
钢板图像 -> RLE 解码 -> 4 通道 Mask -> U-Net 训练 -> 预测 Mask -> RLE 编码 -> Kaggle 提交
```

## 4. 实验结果

我们完成了 Baseline、Full Pipeline、No Augmentation、No Scheduler 等多组实验。当前主要结果如下：

| 实验 | 本地最佳 Val Dice | Private Score | Public Score | 结论 |
|---|---:|---:|---:|---|
| No Augmentation | 0.6373 | 0.84558 | 0.80372 | Private 最优 |
| Baseline | 0.6450 | 0.84233 | 0.80548 | Public 最优，稳定备选 |
| No Scheduler | 0.6281 | 0.83704 | 0.79335 | 略低，可说明调度器作用 |
| Full Pipeline | 0.6613 | 0.74355 | 0.73140 | 本地验证较好，但 Kaggle 分数偏低 |

一个比较有意思的现象是：Full Pipeline 的本地验证结果更高，但 Kaggle 分数反而明显下降。这说明数据增强和训练策略并不是越复杂越好。对于钢板缺陷这种细长纹理型目标，过强增强可能破坏真实缺陷形态，导致泛化下降。

## 5. 智能体使用

本项目中，智能体主要用于：

- 梳理 Kaggle 提交格式；
- 设计项目分工和工程结构；
- 辅助实现 RLE / Dataset 思路；
- 检查 submission 格式风险；
- 设计消融实验；
- 整理报告、PPT 和答辩问题。

通过多轮 Prompt 迭代，我们发现：如果只问“怎么做钢板缺陷检测”，得到的回答往往比较泛；但如果在 Prompt 中加入课程评分标准、算力限制、提交格式和组内分工，输出就会更具体、更适合落地。

## 6. 收获与反思

这次项目最大的收获是完整走通了 Kaggle 图像分割竞赛流程。模型本身很重要，但数据格式、提交格式、实验记录和消融分析同样关键。

后续如果继续优化，可以尝试：

- 针对每个类别单独搜索阈值；
- 对少数类使用类别权重或 Focal Loss；
- 尝试 U-Net++、DeepLabV3+ 等结构；
- 设计更适合工业缺陷的轻量数据增强；
- 使用交叉验证减少验证集波动。

总体来看，U-Net ResNet34 是一个稳定、可解释、适合课程展示的方案。通过消融实验，我们也更清楚地认识到：深度学习项目不能只凭直觉堆优化，必须用实验结果证明每个组件是否真的有效。
