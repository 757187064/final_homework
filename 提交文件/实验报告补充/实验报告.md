## 摘要

本项目选择 Kaggle 竞赛 **Severstal: Steel Defect Detection** 作为深度学习课程大作业。任务目标是对钢板表面缺陷进行 4 类语义分割，并将模型预测的像素级 Mask 转换为 Kaggle 要求的 RLE 编码提交格式。

项目采用 PyTorch 与 U-Net / U-Net ResNet34 作为主要技术路线，围绕数据分析、RLE 编解码、Baseline 构建、Kaggle 推理提交、消融实验和智能体协作记录展开。最终结果中，No Augmentation 方案取得本项目最高 Private Score 0.84558，Baseline 方案取得最高 Public Score 0.80548，可作为稳定备选。实验表明，成熟分割网络能够较好完成工业缺陷检测任务，但更强的数据增强和更复杂训练策略不一定带来更好的榜单泛化，需要结合缺陷形态和数据分布谨慎设计。

**关键词**：语义分割；U-Net；ResNet34；钢板缺陷检测；RLE；消融实验；智能体协作

## 一、竞赛与数据集介绍

### 1.1 赛题背景

Severstal 钢板缺陷检测是一个面向工业表面质检的图像分割任务。钢铁生产过程中，钢板表面可能出现不同类型的缺陷，这些缺陷会影响产品质量、后续加工安全和生产效率。传统人工质检成本高、稳定性有限，因此使用深度学习方法自动识别并定位缺陷具有较强的实际意义。

本赛题与课程中的卷积神经网络、语义分割、迁移学习、数据增强、损失函数设计和模型评估等知识高度相关，适合作为综合实践项目。

### 1.2 任务类型与提交格式

本任务属于 **多类别语义分割任务**。模型需要对每张钢板图像预测 4 个类别的像素级 Mask，并将每个类别的预测结果编码为 RLE。

Kaggle 官方提交文件要求包含两列：

```text
ImageId_ClassId,EncodedPixels
```

测试集共有 5506 张图片，每张图片对应 4 个类别，因此提交文件应包含 22024 行预测结果，加表头共 22025 行。

### 1.3 数据分布分析

根据 02 数据分析结果，训练集中类别分布存在明显不均衡：

| 类别 | 样本数量 |
|---|---:|
| Class 1 | 897 |
| Class 2 | 247 |
| Class 3 | 5150 |
| Class 4 | 801 |
| 有缺陷图片 | 6666 |
| 无缺陷图片 | 5902 |

Class 3 样本最多，Class 2 样本最少。缺陷区域通常细长、不规则，且不同类别形态差异较大，这对模型的局部纹理识别、小目标分割和类别不均衡处理提出了挑战。

## 二、方法设计

### 2.1 Baseline 模型

Baseline 采用 U-Net 结构，Encoder 使用 ResNet34，并加载 ImageNet 预训练权重。U-Net 由编码器和解码器组成，编码器逐步提取高层语义特征，解码器逐步恢复空间分辨率，并通过 skip connection 融合浅层细节特征，因此适合像素级缺陷定位任务。

本项目输入为 RGB 钢板图像，输出为 4 通道缺陷概率图，每个通道对应一种缺陷类别。训练损失采用 BCEWithLogitsLoss 与 Dice Loss 的加权组合，以兼顾像素级分类准确性和缺陷区域重叠质量。

选择 U-Net ResNet34 作为 Baseline 的原因：

- U-Net 是图像分割任务中成熟稳定的基础模型；
- ResNet34 复杂度适中，适合 Kaggle GPU 环境训练；
- ImageNet 预训练 Encoder 有利于提取边缘、纹理和形状特征；
- 模型结构清晰，便于开展消融实验和结果解释。

### 2.2 数据处理与 RLE

项目中的数据处理包括：

- 将 `train.csv` 中的 RLE 标注解码为训练用 4 通道 Mask；
- 兼容 `ImageId_ClassId,EncodedPixels` 和 `ImageId,ClassId,EncodedPixels` 两种训练标注格式；
- 推理后将预测 Mask 重新编码为 Kaggle 要求的 RLE；
- 检查最终 `submission.csv` 是否为两列格式，并确认行数为 22025 行含表头。

### 2.3 训练策略

训练中使用的主要策略包括：

- BCE + Dice 混合损失；
- AMP 混合精度训练，提高 Kaggle GPU 训练效率；
- 学习率调度；
- Debug 小样本配置，用于快速检查流程；
- Best checkpoint 保存，以验证集 Dice 最优模型作为推理模型；
- 多组消融配置，用于分析数据增强、学习率调度、训练轮数、编码器和损失权重的影响。

## 三、实验设计与结果

### 3.1 主实验设置

本项目围绕 Baseline、Full Pipeline、No Augmentation、No Scheduler 四组正式实验进行比较：

| 实验 | 主要变量 | 说明 |
|---|---|---|
| Baseline | U-Net ResNet34 + light augmentation + scheduler | 稳定基础方案 |
| Full Pipeline | 更强增强与更完整训练设置 | 本地验证较好，但榜单下降 |
| No Augmentation | 去除数据增强 | Private 最优主结果 |
| No Scheduler | 去除学习率调度 | 验证 scheduler 影响 |

### 3.2 主实验结果

| 实验 | 本地 Val Dice | Kaggle Private Score | Kaggle Public Score | 结论 |
|---|---:|---:|---:|---|
| Baseline | 0.6450 | 0.84233 | **0.80548** | Public 最优，稳定备选 |
| Full Pipeline | 0.6613 | 0.74355 | 0.73140 | 本地验证较好，但 Kaggle 分数下降 |
| No Augmentation | 0.6373 | **0.84558** | 0.80372 | Private 最优，最终主结果 |
| No Scheduler | 0.6281 | 0.83704 | 0.79335 | 略低，说明 scheduler 有一定作用 |

从 Kaggle 结果看，No Augmentation 和 Baseline 表现最好，而 Full Pipeline 明显下降。这说明在当前设置下，强数据增强并未带来更好的测试集泛化，可能原因是钢板缺陷通常细长、局部且纹理敏感，过强增强可能改变真实缺陷形态。

因此本项目最终口径为：

- **主结果**：No Augmentation，Private Score 0.84558；
- **稳定备选**：Baseline，Public Score 0.80548；
- **反思案例**：Full Pipeline，本地验证更高但 Kaggle 表现下降。

## 八、问题与反思

### 8.1 本地验证与 Kaggle 分数不完全一致

Full Pipeline 本地 Val Dice 较高，但 Kaggle Public/Private Score 明显低于 Baseline 和 No Augmentation。说明本地验证集划分与 Kaggle 测试集分布可能存在差异，单纯依赖本地验证分数容易误判最终泛化效果。

### 8.2 数据增强并非越强越好

No Augmentation 在 Private Score 上表现最好，Strong / Full Pipeline 方案并未带来稳定提升。钢板缺陷具有细长、局部、纹理型特点，过强增强可能破坏真实缺陷形态。

### 8.3 类别不均衡仍需进一步处理

Class 2 样本明显偏少，后续可以进一步尝试类别权重、采样策略、按类别阈值调优或更精细的后处理。

### 8.4 工程复现需要严格控制提交格式

早期 `submission.csv` 曾出现格式风险。本项目最终明确统一为 `ImageId_ClassId,EncodedPixels` 两列，并要求 22025 行含表头，降低了无效提交风险。
