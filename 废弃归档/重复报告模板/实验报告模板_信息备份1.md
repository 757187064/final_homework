## 一、竞赛与数据集介绍

### 1.1 赛题背景

Severstal: Steel Defect Detection 是一个面向工业表面质检的 Kaggle 竞赛。钢铁生产过程中，钢板表面缺陷会影响产品质量、后续加工安全和生产效率。传统人工质检成本较高，且受主观经验、疲劳程度和环境因素影响，稳定性有限。因此，该竞赛要求参赛者利用计算机视觉和深度学习方法自动识别钢板表面缺陷，并定位缺陷区域。

本赛题与深度学习课程中的卷积神经网络、语义分割、迁移学习、数据增强、损失函数设计和模型评价等知识高度相关，适合作为课程综合实践项目。

### 1.2 任务类型与评估指标

本任务属于 **多类别语义分割任务**。模型需要对每张钢板图像预测 4 类缺陷的像素级 Mask，并将每个类别的预测 Mask 转换为 RLE 编码后提交。

Kaggle 官方提交文件要求包含两列：

```text
ImageId_ClassId, EncodedPixels
```

测试集共有 5506 张图像，每张图像需要对应 4 行，即 `xxx.jpg_1` 到 `xxx.jpg_4`，因此最终提交文件应包含 22024 行预测结果，加上表头共 22025 行。

本项目主要使用 Dice 系数衡量分割结果。Dice 反映预测 Mask 与真实 Mask 的重叠程度，数值越高表示模型预测区域与真实缺陷区域越接近。

### 1.3 数据集介绍

数据集由训练图像、测试图像和 `train.csv` 标注文件组成。训练标注以 RLE 形式存储，每个 `ImageId_ClassId` 对应某一张图像的某一类缺陷区域。模型训练时需要将 RLE 解码为 4 通道 Mask；推理提交时又需要将预测 Mask 编码回 RLE。

根据 02 数据分析结果，训练集中类别分布大致如下：

| 类别      | 样本数量 |
| ------- | ----:|
| Class 1 | 897  |
| Class 2 | 247  |
| Class 3 | 5150 |
| Class 4 | 801  |
| 有缺陷图片   | 6666 |
| 无缺陷图片   | 5902 |

数据具有明显类别不平衡特点：Class 3 样本最多，Class 2 样本最少。缺陷区域通常较细长且形态不规则，这对模型的局部纹理识别能力和小目标分割能力提出了较高要求。

## 二、方法

### 2.1 Baseline 方案

Baseline 采用 U-Net 结构，Encoder 使用 ResNet34，并加载 ImageNet 预训练权重。U-Net 是经典语义分割网络，由编码器和解码器组成：编码器逐步提取高层语义特征，解码器逐步恢复空间分辨率，并通过 skip connection 融合浅层细节特征，从而适合像素级缺陷定位。

本项目输入为 RGB 钢板图像，输出为 4 通道缺陷概率图，每个通道对应一种缺陷类别。训练损失采用 BCEWithLogitsLoss 与 Dice Loss 的加权组合，以兼顾像素级分类准确性和缺陷区域重叠质量。

选择 U-Net ResNet34 作为 Baseline 的理由：

- U-Net 是图像分割任务中成熟稳定的基础模型；
- ResNet34 复杂度适中，适合 Kaggle GPU 环境训练；
- ImageNet 预训练 encoder 能提供较好的边缘、纹理和形状特征；
- 模型结构清晰，便于开展消融实验和结果解释。

03 的 Baseline 本地最佳验证结果为：

```text
best_epoch = 14
val_dice = 0.6450
```

Kaggle 提交结果为：

```text
Private Score = 0.84233
Public Score = 0.80548
```

### 2.2 课程知识点应用

- **卷积神经网络 CNN**
  
  - 应用方式：使用 ResNet34 encoder 提取钢板图像的局部纹理、边缘和高层语义特征。
  - 效果：提升模型对缺陷边缘和纹理异常的表达能力。

- **语义分割**
  
  - 应用方式：将任务建模为 4 类像素级 Mask 预测，而不是普通图像分类。
  - 效果：不仅判断图片是否有缺陷，还能定位缺陷区域。

- **迁移学习**
  
  - 应用方式：使用 ImageNet 预训练的 ResNet34 作为 encoder。
  - 效果：在有限训练时间下提高模型初始化质量和收敛稳定性。

- **损失函数设计**
  
  - 应用方式：组合 BCE Loss 与 Dice Loss。
  - 效果：BCE 关注像素级分类，Dice 更贴近最终重叠指标，两者结合更适合分割任务。

- **数据增强**
  
  - 应用方式：实验中尝试 light / strong augmentation，并设置 No Augmentation 消融实验。
  - 效果：结果显示增强策略需要谨慎设计，强增强在当前 Kaggle 分数中未必优于 Baseline。

- **学习率调度**
  
  - 应用方式：使用 scheduler 控制训练过程中的学习率变化，并设置 No Scheduler 消融实验。
  - 效果：No Scheduler 分数略低，可用于说明训练策略对最终效果存在影响。

### 2.3 优化策略与改进

**数据层面**：

- RLE 解码与编码：将 Kaggle 标注转换为训练用 4 通道 Mask，并在推理后重新编码为官方提交格式。
- 类别不平衡分析：通过类别统计发现 Class 2 样本最少，提示后续可考虑类别权重、阈值调优或采样策略。
- 数据增强实验：尝试 light / strong augmentation，并通过 No Augmentation 消融分析其影响。

**模型层面**：

- U-Net ResNet34：在 U-Net 基础上引入 ResNet34 encoder，提升纹理和边缘特征提取能力。
- SMP U-Net ResNet34 验证路线：01 在 Kaggle 上使用 `segmentation_models_pytorch` 跑通训练流程，最高验证 Dice 约 0.7765，说明成熟分割框架和预训练 encoder 对该任务有效。

**训练策略层面**：

- BCE + Dice 混合损失：兼顾像素分类和区域重叠。
- AMP 混合精度：提高 Kaggle GPU 训练效率。
- 学习率调度：通过 No Scheduler 实验验证调度策略的影响。
- Best checkpoint：记录验证集最优模型，而不是只保存最后 epoch。

**后处理与提交层面**：

- 使用 threshold 将概率图二值化；
- 将每张 test image 展开为 4 行提交；
- 检查最终 `submission.csv` 是否为官方两列格式；
- 03 修复早期 submission 格式问题后，已成功提交 Kaggle 并获得有效分数。

### 2.4 消融实验

本项目围绕 Baseline、完整方案和去除关键模块的对照实验进行了多组比较。

| 实验               | 本地最佳 Val Dice | Private Score | Public Score | 结论                     |
| ---------------- | -------------:| -------------:| ------------:| ---------------------- |
| Baseline         | 0.6450        | 0.84233       | 0.80548      | Public 最优，稳定候选         |
| Full Pipeline    | 0.6613        | 0.74355       | 0.73140      | 本地验证较好，但 Kaggle 分数明显偏低 |
| No Augmentation  | 0.6373        | 0.84558       | 0.80372      | Private 最优，最终主结果候选     |
| No Scheduler     | 0.6281        | 0.83704       | 0.79335      | 略低，可说明 scheduler 有一定作用 |


从 Kaggle 结果看，No Augmentation 和 Baseline 表现最好，而 Full Pipeline 明显下降。这说明在当前设置下，强数据增强并没有带来更好的测试集泛化，可能原因是钢板缺陷通常具有细长、局部、纹理型特点，过强增强可能改变真实缺陷形态。后续优化应采用更精细的数据增强、类别阈值调优和类别不平衡处理，而不是简单增加增强强度。

## 八、总结与反思

### 8.1 主要收获

通过本次项目，我们完整经历了 Kaggle 图像分割竞赛流程，包括赛题理解、数据分析、RLE 标注处理、Dataset 构建、U-Net 模型训练、消融实验、结果提交和报告答辩准备。技术上，我们加深了对 CNN、U-Net、迁移学习、损失函数、学习率调度和 Dice 指标的理解；工程上，我们认识到数据格式、提交格式和可复现记录与模型本身同样重要；协作上，我们通过 01/02/03/04 分工，将数据、模型、实验和汇报材料逐步整合成完整项目。

### 8.2 遇到的挑战与解决过程

- **挑战1：submission 格式容易出错**
  
  - 智能体最初生成的代码中没有注意到项目数据集的格式问题，导致生成的submission.csv文件格式与官方要求不符。
  - 解决方式：重新核对官方提交格式，要求每张 test image 输出 4 行，并检查列名和总行数。03 修复后已成功提交 Kaggle。

- **挑战2：实验设想和 Kaggle 分数不完全一致**
  
  - Full Pipeline 在设想中应当具有较高的得分，但 Kaggle 分数较低。
  - 解决方式：报告中不简单宣称 Full Pipeline 最优，而是以 Kaggle leaderboard 为主，分析增强策略可能不适合当前缺陷形态。

- **挑战3：智能体输出可能过于泛化**
  
  - 早期回答容易只给通用模型建议，缺少课程评分和最终提交要求。
  - 解决方式：在 Prompt 中加入评分标准、文件路径、队友分工、Kaggle 格式和当前实验结果，使输出更具体。

- **挑战4：Kaggle 环境存在限制**
  
  - P100 GPU 可能出现 PyTorch CUDA 架构兼容问题；kernel-only 提交要求 Internet Off。
  - 解决方式：训练优先使用 T4 x2；最终提交前保存模型权重和可离线推理版本。


  挑战5：消融实验花费时间久（30小时），容易被设备问题打断导致重新训练
  解决方式：添加断点续训和自动监测并保存脚本

### 8.3 对课程知识的理解深化

本项目使我们更具体地理解了深度学习课程知识在真实任务中的作用。CNN 不只是分类模型的基础，也能作为分割模型的特征提取器；U-Net 的 skip connection 对保留缺陷边缘和细节非常关键；Dice Loss 与 Dice 指标更适合区域重叠评价；迁移学习能在有限算力和数据规模下提高训练效率；消融实验能够帮助我们判断某个模块是否真正有效，而不是凭直觉认为“加了优化就一定更好”。

### 8.4 后续改进方向

如果时间更充裕，后续可以从以下方向继续优化：

- 对 4 个类别分别进行 threshold 搜索，提升小类别识别效果；
- 针对 Class 2 等少数类别尝试类别权重、Focal Loss 或 Tversky Loss；
- 尝试 U-Net++、DeepLabV3+ 或 EfficientNet encoder；
- 设计更适合工业缺陷的轻量增强，而不是直接使用强增强；
- 使用交叉验证或更稳定的数据划分方式减少验证集波动；
- 尝试模型集成和 test-time augmentation；
- 完善离线推理流程，确保 Internet Off 条件下稳定生成 submission。
