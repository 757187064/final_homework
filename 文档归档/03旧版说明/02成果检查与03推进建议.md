## 2. 需要 02 修正或补充的问题

### 问题 1：`any=6666` 的解释口径需要修正

当前记录写成“所有图片均有至少一种缺陷，无干净样本”。这个结论存在风险。

更稳妥的说法应该是：

```text
当前统计表中出现的有缺陷图片数为 6666 张，即至少包含一种缺陷标注的图片为 6666 张。
是否存在无缺陷训练图片，需要进一步统计 train_images 目录下的总图片数，并与有缺陷图片集合做差。
```

原因：

- Severstal 常见数据中训练图片总数不一定等于有缺陷图片数。
- 如果 `train.csv` 只包含有缺陷标注行，那么无缺陷图片不会出现在聚合表中。
- 直接写“所有图片均有缺陷”可能在答辩中被追问。

02 需要补充：

- 统计 `train_images/` 中总图片数。
- 统计有缺陷图片数。
- 计算无缺陷图片数：`总训练图片数 - 有缺陷图片数`。

### 问题 2：比例分母需要说明

当前比例是以 `any=6666` 为分母计算的，所以含义是：

```text
在有缺陷图片集合中，各类别出现比例。
```

如果后续统计出训练集总图片数，应补充另一组比例：

```text
在全部训练图片中，各类别出现比例。
```

### 问题 3：代码兼容声明需要核对

02 记录中写“已在 data.py 中添加兼容处理，同时支持 ImageId/ClassId/EncodedPixels 和 ImageId_ClassId 格式”。但当前仓库中的 `03_模型训练与代码实现/src/severstal/data.py` 仍只接受 `ImageId_ClassId` 和 `EncodedPixels`。

这意味着 03 开始训练前必须先处理数据格式兼容，否则可能读表失败。

## 4. 基于 02 结果，03 现在应该怎么做

03 的第一阶段目标不是马上追高分，而是先保证训练闭环可靠。

### 第一步：统一数据格式

03 先检查实际 `train.csv` 是哪种格式，并统一转换为项目标准格式：

```text
ImageId_ClassId, EncodedPixels
```

如果当前是 `ImageId, ClassId, EncodedPixels` 分列格式，先运行：

```bash
python scripts/normalize_train_csv.py \
  --input data/raw/train.csv \
  --output data/raw/train_standard.csv
```

然后把配置中的 `train_csv` 改成 `train_standard.csv`。

### 第二步：确认无缺陷图片是否进入训练

如果 `train_images/` 中存在未出现在有缺陷标注表里的图片，03 需要决定是否把这些图片作为空 Mask 样本加入训练。

建议加入，因为这样模型能学习“无缺陷背景”，减少测试时误检。

### 第三步：跑 Debug

在 Kaggle 或本地小样本环境先跑：

```bash
python scripts/train.py --config configs/debug.yaml
```

目标：

- 确认 `train.csv` 能读取。
- 确认 Dataset 输出 `(3, H, W)` 图片和 `(4, H, W)` Mask。
- 确认模型 forward、loss、metric、checkpoint 都不报错。

### 第四步：跑 Baseline

Debug 通过后跑：

```bash
python scripts/train.py --config configs/baseline.yaml
```

03 必须保存：

- `history.csv`
- `history.png`
- `best_model.pth`
- `val_predictions/`
- 训练耗时
- 最佳 Val Dice

### 第五步：生成提交文件

```bash
python scripts/infer.py \
  --config configs/baseline.yaml \
  --checkpoint outputs/baseline_unet_resnet34/best_model.pth \
  --output outputs/baseline_unet_resnet34/submission.csv
```

提交 Kaggle 后记录 Public Score。

## 5. 03 的策略建议

基于 02 的类别分布，训练时重点关注类别不平衡：

- Class 2 样本最少，可能召回率低。
- Class 3 样本最多，模型可能偏向多数类。
- Baseline 先使用 BCE + Dice 混合损失。
- 后续可考虑：类别权重、阈值按类别调整、对 Class 2 进行更多可视化检查。

第一轮不要急着改复杂模型，优先顺序：

1. 修好数据格式兼容。
2. 确保无缺陷样本处理正确。
3. 跑通 Debug。
4. 跑 Baseline。
5. 再做 Full Pipeline 和消融实验。
