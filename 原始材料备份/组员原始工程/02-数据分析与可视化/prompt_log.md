## 案例 1：理解任务与项目全貌

### 初始 Prompt

```
这个文件夹里是一个我们小组要完成的深度学习项目。
我需要你先快速阅读除了severstal-steel-defect-detection文件夹以外的
内容，了解你接下来要做哪些工作。
其中，你要仔细阅读文件夹02_数据分析与可视化中的要求文档，
这是我负责的项目工作。
```

### 智能体输出

智能体浏览了整个项目目录，识别出 4 个角色文件夹，精读了 `02_数据分析与可视化` 下的 3 份指导文档和 6 个核心代码文件，同时通读了课程要求、评分标准、实验报告模板等文档，然后给出了完整的项目总览和我的 6 项具体任务清单。

### Prompt 设计思路

- **划定范围**：明确排除数据集文件夹，避免无关内容干扰
- **指定重点**：明确说"仔细阅读 02"，让智能体优先关注我的工作
- **要求输出**：告诉它"了解你要做什么"，让它在总结时带有任务导向

### 迭代心得

这个 Prompt 一次到位，没有迭代。关键点在于**同时给了"广度"（浏览其他文件夹了解整体）和"深度"（仔细阅读 02）两个指令**，让智能体既不会遗漏背景信息，又能聚焦我的任务。

## 案例 2：拆解具体任务

### 初始 Prompt

```
你可以帮我详细总结一下我要做的具体工作是哪些吗？
就用类似我要运行什么，得到什么结果这样的语句来说。
```

### 智能体输出

智能体将我的工作拆解为 6 个可执行步骤，每步都按"执行什么 → 得到什么"的格式表述，清晰列出了运行命令、产出文件、需要理解哪些代码、答辩要回答什么问题。

### Prompt 设计思路

- **指定输出格式**："类似我要运行什么，得到什么结果这样的语句"——这让智能体输出行动导向、可操作的内容，而不是抽象描述
- 帮我把模糊的"我要做数据分析"变成了具体的 6 条待办

### 迭代心得

这个 Prompt 也是一次到位。**对输出格式的明确要求**是最关键的——如果只说"帮我总结"，可能得到笼统的描述，但加了"运行什么，得到什么"的约束后，输出立刻变成了可执行的清单。

## 案例 3：全自动执行数据分析

### 初始 Prompt

```
来吧，就按你说的做
```

### 智能体执行过程

1. 检查数据位置 → 发现数据在 `severstal-steel-defect-detection/` 下
2. 发现 `train.csv` 列名与代码不兼容 → 自动修改 `data.py` 兼容两种格式
3. 检测 Python 环境 → 找到 Python 路径，安装缺失的 opencv
4. 发现 NumPy 版本冲突 → 降级解决
5. 成功运行 `analyze_data.py`，生成 3 个产物文件
6. 读取统计数据，填写分析记录模板
7. 整理 5 个代码文件要点 + 准备 5 个答辩答案

### Prompt 设计思路

- **信任授权**："就按你说的做"——等于把之前讨论好的全部 6 项任务一次性交给了智能体，不逐项指挥
- 这个 Prompt 的精简度达到了极限，但对上下文依赖很高——之前必须充分沟通好"要做什么"

### 迭代心得

这是**上下文依赖型 Prompt 的典型案例**：单个 Prompt 只有 8 个字，但它的威力来自前面两轮已经建立好的任务共识。如果一开始就直接说"来吧"，智能体根本不知道要干什么。这种"先充分讨论 → 再一句话执行"的模式，在复杂任务中非常高效。

## 案例 4：中途纠偏——澄清数据格式

### 过程描述

在生成提交格式说明后，我发现智能体的描述与我看到的 `sample_submission.csv` 对不上，于是提出质疑。

### 关键 Prompt

```
这和sample_submission.csv的格式对不上啊，为什么？
```

### 智能体反应

智能体贴出文件 → 比对代码 → 发现 `infer.py` 只支持 `ImageId_ClassId` 合并列，不支持我的三列分列格式 → 立即修改代码兼容两种格式。

### 迭代心得

- **用户的"纠偏"是高质量 Prompt**——不需要写长篇指令，一句"对不上"就能触发智能体自己去查源码、比对、修复
- 说明**智能体也会依赖代码推断而非外部事实**，用户核对结果很重要

## 案例 5：追问细节——逐概念澄清

### 典型 Prompt 序列

```
train.csv里是什么东西？
sample_submission.csv是什么呢？
这两个csv文件在我这个训练过程中起到什么作用？
你统计的数据是对哪里的样本进行的？
我用于后续训练模型的数据来自哪里？
```

### 智能体输出模式

每个问题都得到了结构化的解释：先说明文件内容（用表或举例），再说明在训练流程中的作用（用箭头流程图），最后说明数据的来龙去脉。

### Prompt 设计思路

- **由浅入深**：先问单个概念是什么 → 再问它们之间的关系 → 最后问整体数据流
- **一步一步来**：不一次性甩出所有问题，而是每理解一个再问下一个
- 这种"逐步引导式提问"让智能体的回答越来越精准

### 迭代心得

复杂的项目理解不是靠一个 Prompt 完成的，而是靠**对话链**。每个回答都会成为下一个问题的上下文，整个对话串起来，就能把整个数据管道从 `train.csv` → RLE 解码 → Dataset 输出 → 模型训练 → Kaggle 提交全部串起来。

## 案例 6：元审视——让智能体总结自己的工作

### 初始 Prompt

```
帮我总结一下啊整个过程中，我都让你这个智能体干了些什么吧。
```

### 后续 Prompt

```
整个过程中你遇到了哪些困难与问题？可以为我列举一些
```

### 智能体输出

两份总结：一份按时间顺序列出我做的所有事情（15 项），一份按困难类型分类列出 5 个问题（环境依赖、数据格式、数据路径、信息核查、外部访问），每个都附原因和解决方案。

### Prompt 设计思路

- **反向利用智能体**——不只让它干活，还让它总结自己干了什么、遇到了什么问题
- 这种总结对写报告的"智能体使用记录"和"失败尝试与反思"部分特别有用
- 智能体对自己碰过的坑记得更清楚，生出的反思比人工回忆更完整

### 迭代心得

这个 Prompt 思路在项目收尾阶段非常实用。与其自己回忆整个过程中智能体做了什么，不如直接让它总结。输出结果可以直接作为报告的素材。

## 智能体使用总结

| 维度 | 评价 |
|------|------|
